# 主题偏好与界面密度设置流程分析报告

## 一、概述

本文档深入分析 Koel 中**主题偏好（Theme Preference）**与**界面密度（View Mode）**两项用户设置，从数据库存储、后端处理、API 传输到前端状态管理与界面渲染的完整端到端流程。重点阐述：

1. 内置主题与自定义主题在**启动加载**、**主题页补拉**和**默认回退**三种场景下的合并方式
2. **自定义主题列表缓存机制**（生效范围、默认失效时间、重新拉取触发条件）
3. **自定义主题返回顺序**对前端展示的影响
4. 电台列表界面密度从偏好读取到具体渲染分支的分配过程

### 2.3 自定义主题存储

自定义主题存储在独立的 `themes` 表中，由 [Theme](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/app/Models/Theme.php) 模型表示，使用 ULID 主键，归属于用户（`user_id` 外键）。`properties` 字段通过 [ThemePropertiesCast](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/app/Casts/ThemePropertiesCast.php) 转换为 [ThemeProperties](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/app/Values/Theme/ThemeProperties.php) 只读值对象。

ThemeProperties 包含 6 个 CSS 变量属性：


## 三、内置主题与自定义主题的合并方式

### 3.1 前端主题数据结构

[themeStore.ts](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts) 的核心状态是一个扁平数组：

```typescript
state: reactive({
  themes,  // 初始值为 themes.ts 导出的 18 个内置主题
}),
```

[themes.ts](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/config/themes.ts) 导出的 18 个内置主题**不含** `is_custom` 字段（等同于 `undefined`，在布尔判断时为 `falsy`），这是区分内置/自定义的关键标识。

每个主题对象的通用结构：

```typescript
interface Theme {
  id: string           // 唯一标识
  name: string         // 显示名称
  thumbnail_color?: string   // 预览卡片背景色
  thumbnail_image?: string   // 预览卡片缩略图 URL
  properties?: Record<string, string>  // CSS 变量覆盖映射
  is_custom?: boolean  // 仅自定义主题为 true
}
```

### 3.2 场景一：启动加载（Application Bootstrap）

启动加载是应用初始化时一次性获取数据的过程，由 [commonStore.init()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/commonStore.ts#L60-L78) 编排：

```typescript
async init() {
  Object.assign(this.state, await http.get<CommonStoreState>('data'))

  userStore.init(this.state.current_user)
  preferenceStore.init(this.state.current_user.preferences)   // ① 加载偏好（含 theme 键）
  // ... 其他 store 初始化
  themeStore.init(this.state.current_theme || themeStore.getCurrentTheme())  // ② 加载当前主题
}
```

#### 后端返回逻辑

[FetchInitialDataController.php](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/app/Http/Controllers/API/FetchInitialDataController.php#L46-L49) 中 `current_theme` 的决定逻辑：

```php
$theme = $licenseStatus->isValid()
    ? $themeRepository->findUserThemeById($user->preferences->theme, $user)
    : null;
```

**分支决策树：**

```
用户偏好 theme 值
    │
    ├─ License 无效 → current_theme = null
    │
    └─ License 有效 → 用 theme 值在 themes 表查找当前用户的自定义主题
          │
          ├─ 找到（该 id 是自定义主题的 ULID）→ current_theme = ThemeResource
          │
          └─ 未找到（该 id 是内置主题名如 'classic'）→ current_theme = null
```

关键点：后端只在 `current_theme` 字段中返回**自定义主题对象**。内置主题不经过此字段传递——前端已有内置主题列表，只需传递 ID 即可定位。

#### 前端合并逻辑

[themeStore.init()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L37-L55)：

```typescript
init(theme: Theme | Theme['id'] = 'classic') {
  // ... 记录 CSS 默认属性 + 设置 StyleObserver

  if (typeof theme === 'object' && theme.is_custom) {
    this.state.themes.push(theme)  // ← 将后端返回的自定义主题追加到数组末尾
  }

  this.setTheme(theme)  // ← 应用主题
}
```

**启动时主题合并结果：**

| 来源 | 数量 | 合并方式 | 在数组中位置 |
|------|------|----------|------------|
| [themes.ts](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/config/themes.ts) 内置 | 18 | 初始值（`state.themes` 直接引用） | [0] ~ [17] |
| `current_theme` 当前自定义主题 | 0 或 1 | `this.state.themes.push(theme)` | 末尾 [18] |

**注意**：启动时**仅推送当前使用的那一个自定义主题**，不会加载用户的所有自定义主题。

#### setTheme 中的回退逻辑

[themeStore.setTheme()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L61-L78) 负责将主题应用到 DOM：

```typescript
setTheme(theme?: Theme | Theme['id']) {
  if (theme === undefined) {
    return this.setTheme(this.getCurrentTheme())  // 回退到当前偏好主题
  }

  if (typeof theme === 'string') {
    theme = this.getThemeById(theme) ?? this.getDefaultTheme()  // ← 默认回退
  }

  document.documentElement.setAttribute('data-theme', theme.id)
  const properties = { ...this.defaultProperties, ...(theme.properties ?? {}) }

  for (const key in properties) {
    document.body.style.setProperty(key, properties[key])
  }

  preferences.theme = theme.id
}
```

**默认回退链：**

```
setTheme(themeId)
    │
    ├─ themeId 是字符串
    │     │
    │     ├─ getThemeById(themeId) 找到 → 使用该 Theme 对象
    │     │
    │     └─ getThemeById(themeId) 未找到（如自定义主题已被删除）
    │           │
    │           └─ getDefaultTheme() → 返回 id='classic' 的内置主题
    │
    └─ themeId 是 undefined
          │
          └─ getCurrentTheme()
                │
                ├─ preferences.theme 有值且能找到 → 使用
                │
                └─ preferences.theme 无值或找不到 → getDefaultTheme()
```

[getDefaultTheme()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L89-L91) 硬编码返回 `classic`：

```typescript
getDefaultTheme() {
  return this.getThemeById('classic')!
}
```

**重要细节**：`classic` 主题在 [themes.ts](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/config/themes.ts#L20-L24) 中的定义**不含 `properties` 字段**：

```typescript
{
  id: 'classic',
  name: 'Classic',
  thumbnail_color: '#181818',
}
```

这意味着 `classic` 主题应用时 `theme.properties` 为 `undefined`，`setTheme` 中 `...(theme.properties ?? {})` 展开为空对象，最终 `properties = { ...this.defaultProperties }`——即所有 CSS 变量恢复为初始默认值，实现了「重置为默认」的效果。

### 3.3 场景二：主题页补拉（Theme Preferences Page Load）

当用户导航到主题偏好页面时，前端需要补拉用户的**全部**自定义主题。

[ThemePreferences.vue](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/components/profile-preferences/theme/ThemePreferences.vue#L36-L40)：

```typescript
onMounted(async () => {
  if (isPlus.value) {
    await themeStore.fetchCustomThemes()  // ← 仅 Plus 用户触发
  }
})
```

[themeStore.fetchCustomThemes()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L109-L112)：

```typescript
async fetchCustomThemes() {
  const customThemes = await cache.remember('custom-themes', async () => await http.get<Theme[]>('themes'))
  this.state.themes = uniqBy(this.state.themes.concat(customThemes), 'id')
}
```

#### 补拉合并策略详解

**1. API 调用**：请求 `GET /api/themes`，由 [ThemeController::index()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/app/Http/Controllers/API/ThemeController.php#L25-L28) 返回当前用户的**所有自定义主题**（带 `#[RequiresPlus]` 属性，非 Plus 用户无法访问）。

**2. 内存缓存**：通过 [cache.remember()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/services/cache.ts#L56-L59) 实现请求级缓存。

**3. 数组合并**：`this.state.themes.concat(customThemes)` 将现有列表（含内置 + 启动时推送的那个自定义主题）与新获取的自定义主题列表拼接。

**4. 去重**：`uniqBy(..., 'id')` 按 `id` 去重——因为启动时已通过 `init()` 的 `push` 操作添加了当前使用的自定义主题，此步骤确保不会出现重复项。`uniqBy` 保留**首次出现的元素**，即内置主题和启动时已推送的自定义主题不会被覆盖。

**补拉后主题合并结果：**

| 来源 | 数量 | 合并方式 | 去重依据 |
|------|------|----------|---------|
| 内置主题 | 18 | 初始值 | `id` 全局唯一 |
| 启动时推送的当前自定义主题 | 0~1 | 已在数组中 | `uniqBy` 保留首次出现 |
| API 返回的全部自定义主题 | 0~N | `concat` 后 `uniqBy` 去重 | `id` 去重（ULID 保证唯一） |

### 3.4 场景三：默认回退（Default Fallback）

默认回退在以下三种情况下触发：

#### 情况 A：偏好中无主题设置

[preferenceStore](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/preferenceStore.ts#L42) 默认值 `theme: 'classic'`。如果后端未返回 `theme` 字段，`Object.assign(this.state, preferences)` 后 `theme` 保持为 `classic`。

[themeStore.getCurrentTheme()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L93-L95)：

```typescript
getCurrentTheme() {
  return preferences.theme
    ? (this.getThemeById(preferences.theme) ?? this.getDefaultTheme())
    : this.getDefaultTheme()
}
```

- `preferences.theme` 为 `classic` → `getThemeById('classic')` 返回内置主题 → 正常应用
- `preferences.theme` 为空字符串 → falsy → 直接回退到 `classic`

#### 情况 B：自定义主题已被删除

用户删除一个当前正在使用的自定义主题时：

[themeStore.destroy()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L114-L128)：

```typescript
async destroy(theme: Theme) {
  if (!theme.is_custom) return  // 内置主题不可删除

  const isCurrentTheme = this.isCurrentTheme(theme)

  await http.delete(`themes/${theme.id}`)
  this.state.themes = this.state.themes.filter(({ id }) => id !== theme.id)  // 从列表移除
  cache.remove('custom-themes')  // 清除缓存，下次补拉时不会恢复

  if (isCurrentTheme) {
    this.setTheme(this.getDefaultTheme())  // ← 回退到 classic
  }
}
```

回退过程：`getDefaultTheme()` → `getThemeById('classic')` → 应用 `classic` 主题 → `preferences.theme` 被写为 `'classic'` → PATCH API 同步到后端

#### 情况 C：后端返回 current_theme 为 null 且偏好 ID 无匹配

此情况发生在 License 失效后：后端不返回 `current_theme`（为 null），且 `preferences.theme` 中保存的是自定义主题的 ULID。

[commonStore.init()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/commonStore.ts#L75) 中：

```typescript
themeStore.init(this.state.current_theme || themeStore.getCurrentTheme())
```

- `current_theme` 为 null → falsy → 走 `themeStore.getCurrentTheme()`
- `getCurrentTheme()` 内 `preferences.theme` 为 ULID → `getThemeById(ULID)` 在内置列表中找不到 → 回退到 `getDefaultTheme()` → `classic`

## 四、自定义主题列表缓存机制详解

### 4.1 缓存存储介质与单例模式

自定义主题列表缓存由 [cache.ts](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/services/cache.ts) 实现，核心是一个**内存中的 `Map` 对象**：

```typescript
const DEFAULT_EXPIRATION_TIME = 1000 * 60 * 60 * 24 // 1 day

export class Cache {
  private storage = new Map<
    any,
    {
      expires: number
      value: any
    }
  >()
}

export const cache = new Cache()  // ← 只实例化一次，导出单例
```

**缓存存储特性：**

| 属性 | 说明 |
|------|------|
| **存储介质** | `new Map()` 内存对象，而非 localStorage 或 IndexedDB |
| **单例模式** | 整个应用生命周期内仅实例化一次，所有组件共享同一个缓存实例 |
| **缓存键** | 硬编码字符串 `'custom-themes'`（由 `normalizeKey` 标准化） |
| **生效范围** | 当前 SPA 运行期间有效；浏览器刷新、标签页关闭、窗口重开都会导致内存释放，缓存自然失效 |
| **用户隔离** | 登出操作（[authService.destroy()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/services/authService.ts#L51-L54)）只清除 localStorage 中的 token，**不调用 `cache.clear()`**。但登出后页面通常跳转刷新，内存也会释放 |
| **测试隔离** | 仅在测试代码 [TestHarness.ts](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/__tests__/TestHarness.ts#L55) 的 `afterEach` 中调用 `cache.clear()` 保证测试用例之间隔离 |

### 4.2 默认失效时间

[cache.ts#L1](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/services/cache.ts#L1) 中定义的默认过期时间：

```typescript
const DEFAULT_EXPIRATION_TIME = 1000 * 60 * 60 * 24 // 1 天 = 86,400 秒
```

[cache.remember()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/services/cache.ts#L56-L59) 的实现：

```typescript
async remember<R>(key: any, resolver: () => R | Promise<R>, seconds: number = DEFAULT_EXPIRATION_TIME) {
  this.hit(key) || this.set(key, await resolver(), seconds)
  return this.get(key) as Awaited<R>
}
```

[cache.set()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/services/cache.ts#L24-L29) 中过期时间计算：

```typescript
public set(key: any, value: any, seconds: number = DEFAULT_EXPIRATION_TIME) {
  this.storage.set(Cache.normalizeKey(key), {
    value,
    expires: Date.now() + seconds * 1000,  // ← 秒转换为毫秒
  })
}
```

`themeStore.fetchCustomThemes()` 调用时**未传递第三个参数** `seconds`：

```typescript
async fetchCustomThemes() {
  const customThemes = await cache.remember('custom-themes', async () => await http.get<Theme[]>('themes'))
  // ...
}
```

因此自定义主题列表的缓存有效期为 **86,400 秒（24 小时）**。

**过期检测逻辑**（[cache.miss()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/services/cache.ts#L35-L50)）：

```typescript
public miss(key: any) {
  key = Cache.normalizeKey(key)

  if (!this.storage.has(key)) {
    return true  // 缓存不存在
  }

  const { expires } = this.storage.get(key)!

  if (expires < Date.now()) {
    this.storage.delete(key)  // 过期则立即删除
    return true
  }

  return false  // 缓存有效
}
```

### 4.3 触发重新拉取的操作

**触发缓存失效（重新拉取）的三种操作：**

| 操作 | 代码位置 | 具体行为 |
|------|----------|----------|
| **创建新主题** | [themeStore.store()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L101-L107) | 调用 `cache.remove('custom-themes')` 主动清除缓存；下次打开主题页时 `cache.remember()` 检测到 miss，重新请求 API |
| **删除主题** | [themeStore.destroy()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L114-L128) | 调用 `cache.remove('custom-themes')` 主动清除缓存；同上 |
| **缓存自然过期** | [cache.miss()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/services/cache.ts#L44-L47) | 24 小时过期后自动删除条目，下次请求重新拉取 |

**不会触发重新拉取的场景：**

1. 用户在不同页面间来回导航（无刷新）——缓存持续有效
2. 用户在主题页不进行任何增删操作，只是切换/应用不同主题——不影响缓存
3. 用户在其他功能区操作（播放歌曲、创建播放列表等）——缓存键 `custom-themes` 独立不受影响
4. 用户关闭主题页，在同一会话内再次打开主题页——缓存仍然有效，直接返回

**创建主题时的 store() 完整流程：**

```typescript
async store(data: ThemeData) {
  const theme = await http.post<Theme>('themes', data)  // 后端持久化
  this.state.themes.unshift(theme)                      // 立即插入本地数组头部
  cache.remove('custom-themes')                          // ← 清除缓存
  return theme
}
```

**关键设计点**：
- `unshift` 保证新创建的主题**立即**在主题页顶部显示，即使缓存没有重新拉取
- 缓存清除是**异步**的，下一次打开主题页时才会触发重新拉取

## 五、自定义主题返回顺序对前端展示的影响

### 5.1 后端排序逻辑

[ThemeRepository.getAllByUser()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/app/Repositories/ThemeRepository.php#L14-L17)：

```php
public function getAllByUser(User $user): Collection
{
    return $user->themes->sortByDesc('created_at');
}
```

**后端排序规则**：`sortByDesc('created_at')` 按 `created_at` 字段**倒序**排列，即**最新创建的主题排在最前面**。

### 5.2 前端合并时的顺序控制

#### A. 启动加载时的顺序

[themeStore.init()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L49-L52)：

```typescript
if (typeof theme === 'object' && theme.is_custom) {
  this.state.themes.push(theme)  // 追加到数组末尾
}
```

此时数组结构为：

```
[0] Classic (内置)
[1] Mono (内置)
...
[17] Cat (内置)
[18] 当前使用的自定义主题 (push 到末尾)
```

#### B. 主题页补拉时的顺序

[themeStore.fetchCustomThemes()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L109-L112)：

```typescript
async fetchCustomThemes() {
  const customThemes = await cache.remember('custom-themes', async () => await http.get<Theme[]>('themes'))
  this.state.themes = uniqBy(this.state.themes.concat(customThemes), 'id')
}
```

**顺序影响分析**：

1. `this.state.themes` 目前是 `[内置(18) + 当前自定义主题(1)]`
2. `customThemes` 是后端返回的数组，顺序为 `sortByDesc('created_at')`（最新的在前）
3. `concat` 之后：`[内置(18), 当前自定义主题, 自定义主题1(最新), 自定义主题2, ..., 自定义主题N(最旧)]`
4. `uniqBy('id')` 去重，保留**首次出现**的元素——所以当前自定义主题不会被后面 API 返回的同 id 元素覆盖

**补拉后的最终数组结构**：

```
[0] Classic (内置)
[1] Mono (内置)
...
[17] Cat (内置)
[18] 当前使用的自定义主题 (启动时 push 的)
[19] 最新创建的自定义主题 (API 排序第 1)
[20] 次新创建的自定义主题 (API 排序第 2)
...
[18+N-1] 最旧的自定义主题 (API 排序最后)
```

**注意**：如果当前使用的自定义主题恰好是**最新创建**的（API 返回的 customThemes 数组第 1 位），concat 后它会在 [18] 出现一次，在 [19] 又出现一次，`uniqBy` 会保留 [18] 位置的那个，[19] 被丢弃。

#### C. 创建新主题时的顺序

[themeStore.store()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L101-L107)：

```typescript
async store(data: ThemeData) {
  const theme = await http.post<Theme>('themes', data)
  this.state.themes.unshift(theme)  // ← unshift 插入数组头部
  cache.remove('custom-themes')
  return theme
}
```

**unshift 的特殊处理**：

- 新创建的主题插入**数组的最前面**，即索引 [0] 位置
- 这意味着新创建的自定义主题会**出现在内置主题之前**
- 但在 UI 层面，[ThemePreferences.vue](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/components/profile-preferences/theme/ThemePreferences.vue#L29-L30) 通过 `filter(theme => !theme.is_custom)` 和 `filter(theme => theme.is_custom)` 分开展示，所以顺序不影响分组，但在自定义主题组内部，最新创建的排在最前

#### D. 删除主题时的顺序

[themeStore.destroy()](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.ts#L114-L128)：

```typescript
this.state.themes = this.state.themes.filter(({ id }) => id !== theme.id)
```

`filter` 会**保留原有相对顺序**，只移除匹配 id 的元素，不影响其他元素的排列。

### 5.3 UI 展示顺序

[ThemeList.vue](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/components/profile-preferences/theme/ThemeList.vue#L1-L7) 直接按数组顺序渲染：


**完整 UI 展示顺序总结**：

```
┌─────────────────────────────────────────────────────────────────────┐
│  Built-in Themes 区域（filter(!is_custom)）                           │
│                                                                     │
│  固定顺序（themes.ts 定义顺序）:                                      │
│  Classic → Mono → Violet → Oak → Slate → Madison → Astronaut → ...  │
│  （共 18 个，顺序永不改变）                                            │
├─────────────────────────────────────────────────────────────────────┤
│  Custom Themes 区域（filter(is_custom)）                             │
│                                                                     │
│  排序规则（综合了启动、补拉、创建的顺序影响）:                           │
│  ┌─────────────────────┬──────────────────────────────────────────┐ │
│  │ 场景                │ 自定义主题组内的显示顺序                   │ │
│  ├─────────────────────┼──────────────────────────────────────────┤ │
│  │ 从未创建过主题      │ 不显示 Custom Themes 区域                 │ │
│  │ 创建了 N 个主题     │ 最新创建的主题 → 次新 → ... → 最旧的主题  │ │
│  │ 刚创建了一个新主题  │ 新主题会 unshift 到自定义组的最前面       │ │
│  │ 删除了一个主题      │ 被删主题消失，其他保持相对顺序             │ │
│  │ 当前在用的是自定义  │ 该主题在数组中出现两次，uniqBy 保留首次   │ │
│  │ 主题（且未补拉）    │ （不会影响展示顺序）                       │ │
│  └─────────────────────┴──────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────┘
```

**顺序影响的特殊场景**：

1. **刚创建新主题时**：`unshift` 到数组头部，在自定义主题组内排第一；下一次打开主题页（或缓存失效后重新拉取），后端按 `sortByDesc('created_at')` 返回，仍然是最新的排第一，顺序一致。

2. **测试用例验证**：[themeStore.spec.ts#L116](file:///d:/fz/0601-1/solo-dogfeeding/code/46-koel/resources/assets/js/stores/themeStore.spec.ts#L116) 测试创建主题后 `expect(themeStore.all[0]).toEqual(createdTheme)`，验证了 `unshift` 到数组首位的行为。

3. **内置主题位置不变**：由于 `concat` 始终是把自定义主题拼接到现有数组后面，所以内置主题（数组前 18 位）永远排在任何自定义主题之前，除非用户调用了 `unshift`（仅创建新主题时会发生一次）。

### 6.7 电台列表与专辑列表密度实现的差异

两者采用相同的偏好→布局映射逻辑和相同的 `AlbumOrArtistCard` 组件，但在网格容器上有差异：

| 特性 | 专辑列表 (AlbumListScreen) | 电台列表 (RadioStationListScreen) |
|------|--------------------------|----------------------------------|
| 网格容器 | `VirtualGridScroller`（虚拟滚动） | `GridListView`（普通网格） |
| 行间距控制 | `:class="itemLayout === 'full' ? 'gap-y-5' : 'gap-y-3'"` | 由 `GridListView` 的 `.as-list` 类控制 |
| 最小列宽 | `minItemWidth` computed 传给 scroller | 由 `GridListView` CSS 控制 |
| 数据加载 | 分页加载（`paginate`） | 一次性加载（`fetchAll`） |

专辑列表因数据量大使用虚拟滚动，需要手动计算 `minItemWidth` 和行间距；电台列表数据量小，使用简单网格即可。
